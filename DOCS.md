# Registan Travel: документация для защиты

Документ для устного ответа по Lab Work 5 (CSIT248). Здесь объясняется, что делает каждый файл, почему написано именно так и что отвечать на типичные вопросы.

## 1. Общая картина

Два рабочих экрана: главная (`index.html`) и бронирование (`booking.html`). Один общий `css/style.css` (как требует задание). Для сравнения есть третья страница на Bootstrap (`index-bootstrap.html`) со своим маленьким `css/bootstrap-theme.css`.

Заказчица попросила три вещи, и каждая решена так:

| Пожелание | Решение |
|---|---|
| «Сначала телефон» | mobile first: базовые правила для телефона, `min-width` только добавляет |
| «Цена до отправки формы» | живой пересчёт на событиях `input` и `change` |
| «Покажите разницу с Bootstrap» | `index-bootstrap.html` и сравнение строк CSS (раздел 6) |

## 2. Файлы по одному

### index.html
Главная. Шапка (`header.site-header`) с логотипом, меню `nav.main-nav`, кнопкой темы и кнопкой «Book now». Hero в виде арки (`#hero`): внутри контейнер `#registan-3d` для canvas и запасное фото. Секция `#tours` с тремя `div.card`. Подвал с контактами и авторами фото. Скрипты стоят в конце `body`, а `theme.js` в `head`, чтобы тема применилась до первой отрисовки. В HTML нет атрибутов `style` и тегов `<style>`.

### booking.html
Форма `#booking-form` с атрибутом `novalidate` (свои сообщения вместо браузерных). Поля: имя, email, тур (`select` с тремя турами), число путешественников (1–12), дата, кнопка. Каждое поле лежит в `.field` и связано с текстом ошибки через `aria-describedby`. У обязательных меток класс `required`, звёздочку рисует CSS через `::after`, в HTML её нет. Рядом блок цены и боковая колонка «Good to know».

### index-bootstrap.html
Та же главная на Bootstrap 5.3.3 с CDN: `navbar`, `container / row / col-*`, `card`. Бренд-цвета добавлены в `css/bootstrap-theme.css`.

### js/main.js (страница бронирования)
- `calculateTotal(price, people)`: чистая функция, возвращает `{subtotal, discount, total}`. Скидка 10% от 5 человек (`DISCOUNT_FROM`, `DISCOUNT_RATE`). Округление до центов: `Math.round(x * 100) / 100`, потому что дроби в JS неточны.
- `formatUSD(amount)`: «360 USD» без лишних нулей, «157.50 USD» с копейками.
- `getTourPrice()`, `getTourName()`, `getTravellers()`: читают данные из DOM. Цена тура хранится в `data-price` у `option`, а не зашита в код.
- `isValidTravellers(n)`: целое число от 1 до 12. Дробное и 13 отклоняются.
- `updatePrice()`: строит строку «Total: 3 × 120 USD = 360 USD» (при скидке: «5 × 120 USD = 600 USD − 10% = 540 USD»). При неверном числе показывает «Total: —».
- `onPriceChanged()`: короткий «подскок» суммы через Web Animations API, если нет `prefers-reduced-motion`.
- `showFieldError()` / `clearFieldError()`: класс `is-error` на `.field`, `aria-invalid="true"`, текст в элемент `id + '-error'`.
- `showMessage(type, text)`: общее сообщение (error или success). Используется `textContent`, а не `innerHTML`, чтобы введённое имя не могло вставить HTML.
- `isValidEmail()`: по заданию нужен `@`; плюс он не первый и не последний символ («@mail.ru» отклоняется).
- `handleSubmit(event)`: `event.preventDefault()` (страница не перезагружается), проверка имени, email, числа людей и даты (не в прошлом). При ошибках: красное сообщение и фокус на первое неверное поле. Иначе зелёное подтверждение с именем, туром, датой и суммой; кнопка блокируется («Request sent») и снова включается при редактировании (`resetFormState()`).
- `preselectTourFromUrl()`: `booking.html?tour=khiva` выбирает тур в списке; нужна для «влёта» с карточки.

Доступность (aria): `aria-describedby` связывает поле с ошибкой, `aria-invalid` помечает неверные поля, сообщение получает фокус, поэтому скринридер читает результат.

### js/theme.js
Подключён в `head`, чтобы не было белой вспышки в тёмной теме. Порядок выбора темы: параметр `?theme=` в адресе, затем `localStorage` (ключ `registan-theme`), затем светлая. `applyTheme()` ставит `data-theme` и `data-bs-theme` (для Bootstrap) на `<html>` и отправляет событие `themechange`, которое слушает 3D-сцена. Обращения к `localStorage` и `sessionStorage` обёрнуты в `try/catch` (приватный режим может их запретить). Кроме того, ставит служебные классы `intro-seen` и `arrive-from-card` до отрисовки. Кнопка темы обновляет `aria-label`.

### js/cards.js
- Наклон: на `pointermove` считает положение курсора в долях от 0 до 1 и записывает в CSS-переменные `--rx`, `--ry` (до ±8°) и `--mx`, `--my` (блик). Сам поворот и блик рисует CSS, JS только считает числа.
- Клик по всей карточке открывает тур, при этом настоящая ссылка `a.card-link` остаётся в разметке для клавиатуры и скринридера. Ctrl/Shift-клик и выделение текста не перехватываются.
- `flyInto()` и `expand()`: «влёт» из нескольких шагов, около 3 секунд: карточка приподнимается, соседние отступают и размываются; фото раскрывается на весь экран через `clip-path`, всплывает название; затем всё растворяется в тёмно-синем и открывается `booking.html?tour=…`. Страховочный таймер гарантирует переход, даже если вкладку свернули.
- Анимация включается только при `(hover: hover) and (prefers-reduced-motion: no-preference)`; на телефоне и при «меньше движения» тур открывается сразу.

### js/scroll.js
Кнопка «Choose a tour» плавно прокручивает к заголовку секции туров. Высота шапки берётся из CSS (`scroll-padding-top`), число не дублируется. После прибытия на секцию на время вешается класс `is-arriving` (подсветка карточек). При `prefers-reduced-motion` прокрутка мгновенная.

### js/registan-3d.js
Описана в разделе 5.

### js/vendor/
`three.min.js` (Three.js r149, MIT), `GLTFLoader.js`, `meshopt_decoder.js` (для необязательной реальной модели). Лежат в проекте, поэтому интернет для главной не нужен.

## 3. Архитектура CSS (css/style.css)

Файл разбит на 11 нумерованных разделов (оглавление в начале файла): переменные, база, шапка и меню, кнопка темы, кнопки, hero, карточки, подвал, бронирование, анимации, медиа-запросы.

**Токены.** В `:root` лежат бренд-цвета (`--night #0B1F4B`, `--gold #E0A526`, `--brick #C0392B`, `--sand #FAF6EE`) и «смысловые» переменные (`--bg`, `--surface`, `--text`, `--muted`, `--heading`, `--line`…). В правилах используются именно смысловые переменные, поэтому тёмная тема меняет несколько значений, а не переписывает стили.

**Светлая и тёмная тема.** Блок `:root[data-theme="dark"]` переопределяет смысловые переменные. Атрибут ставит `theme.js`. Атрибут выбран, а не класс, потому что он совпадает по смыслу с `data-bs-theme` у Bootstrap.

**Mobile first.** Базовые правила без медиа-запросов описывают телефон (одна колонка: `grid-template-columns: minmax(0, 1fr)`). Дальше только добавляется: `@media (min-width: 768px)` даёт 2 колонки, `(min-width: 1200px)` даёт 3. Отдельный `max-width: 399px` прячет слово в логотипе на самых узких экранах (остаётся знак-арка, слово доступно скринридеру).

**box-sizing.** `*, *::before, *::after { box-sizing: border-box }`: padding и border входят в заданную ширину. Это же групповой селектор из задания.

**Селекторы по заданию.** ID-селектор: `#hero`, `#hero h1`. Групповой: правило с `*, *::before, *::after`. `<span>`: акцентное слово в заголовке hero и другие.

**Каскад и специфичность.**
- LVHA: `.main-nav a:link`, затем `:visited`, `:hover`, `:active`. У всех равная специфичность, побеждает правило ниже, поэтому порядок важен.
- `.site-header .header-cta { display: none }` написан двумя классами. У `.btn` ниже по файлу есть своё `display`; при одинаковой специфичности победило бы оно, и кнопка торчала бы на телефоне. Повышение специфичности вместо `!important` решает проблему честно (за `!important` минус 2 балла). На планшете то же правило внутри `@media (min-width: 768px)` возвращает `display: inline-block`.

**Бейдж.** `.card { position: relative }`, `.badge { position: absolute; top; right }`: бейдж привязан к своей карточке. Без `relative` отсчёт шёл бы от окна (Bug 2).

**Меню.** Текущая страница: стеклянная подложка и золотая нижняя черта через `a.active::after` с `border-bottom`. Hover: золотой фон.

**Фокус.** Базовое правило `:focus-visible` даёт золотой `outline` с отступом; у полей формы своя заметная рамка и тень. Фокус не убирается, он оформлен.

**Анимации.** Анимируются только `opacity` и `translate`, они дёшевы для браузера. Свойство `translate` (а не `transform`) выбрано, чтобы не конфликтовать с `transform: scale()` у нажатой кнопки: это разные свойства, они складываются. Анимации завёрнуты в `@media (prefers-reduced-motion: no-preference)`, а в конце файла `@media (prefers-reduced-motion: reduce)` гасит оставшиеся переходы.

**Hover только для мыши.** Эффекты наведения лежат в `@media (hover: hover)`: на телефоне `:hover` «залипает» после тапа.

**«Жидкое стекло».** Полупрозрачный фон шапки плюс `backdrop-filter: blur(20px) saturate(180%)` (с префиксом `-webkit-`), блик по кромке через `inset box-shadow` и псевдоэлемент `::before` с `pointer-events: none`.

**Ограничения.** В CSS нет `!important`, в HTML нет inline-стилей. Единственное, что JS пишет в стиль во время работы, это CSS-переменные карточек и временные слои «влёта» через DOM-API; атрибута `style` в разметке нет.

## 4. Part B: форма

- Метки над полями, поля шириной 100% (вместе с `border-box`).
- `:focus` заметный: золотая обводка, поле не остаётся «безымянным».
- Звёздочка: `.field label.required::after` с `content` и цветом brick red. В HTML её нет, это проверяет автотест.
- Валидация `novalidate` плюс свой JS: единое оформление и тексты ошибок.

## 5. 3D-сцена (registan-3d.js)

1. **Сцена из примитивов.** Функции `madrasah()`, `minaret()`, `dome()`, `archGeometry()` собирают здания из боксов, цилиндров и полусфер. Узоры изразцов рисует `makeTexture()` на `<canvas>` (звёзды, ромбовая сетка, `spandrelTexture()` для угловых элементов арки). Внешних 3D-файлов нет, поэтому сцена лёгкая и работает с диска.
2. **Небо.** Большая сфера с собственным шейдером: градиент от горизонта до зенита плюс диски солнца и луны. Цвета неба берутся из палитры в трёх точках (день, закат, ночь) через `threeStop()`.
3. **Полоборота небесной сферы.** Переменная `turn` (0 день, 1 ночь, 2 снова день…). `applySky(turn)` считает угол `NOON − π·turn`, ставит солнце, а луну в противоположную точку. Поэтому закат и восход идут всегда в одну сторону: солнце садится справа, луна поднимается слева. «Темнота» `t` считается по высоте солнца через `smoothstep`.
4. **Свет.** `HemisphereLight` (рассеянный), `DirectionalLight` для солнца с тенями (карта 2048) и для луны. Фонари включаются при `t` около 0.45–0.72, ниши позже, окна по одному (у каждого свой порог `threshold`): ночью площадь «зажигается» постепенно. Звёзды (`Points`) проявляются при `t` больше 0.62. Лёгкое мерцание фонарей (`flicker`) выключено при `reduce-motion`.
5. **Камера.** `setViewOffset` (эффект shift-объектива) держит горизонт и вертикали ровными, а `resize()` подбирает fov под ширину арки. Облёт: перетаскивание меняет `yaw` (360°) и высоту; значения догоняются плавно (`shownYaw += (yaw − shownYaw) × 0.12`). Двойной клик возвращает вид. Пока человек не трогал сцену, камера слегка покачивается и следит за курсором (параллакс).
6. **Интро один раз.** Сначала фото, через 3 секунды класс `scene-live` растворяет его и показывает 3D. Флаг в `sessionStorage` не даёт повторять интро при возврате на главную.
7. **Экономия.** `IntersectionObserver` не рисует кадры, пока сцена вне экрана, и `document.hidden` тоже останавливает рендер. Если нет WebGL, скрипт тихо выходит, остаётся фото.

## 7. Part D: баги клиента

**Bug 1. Посещённые ссылки не золотятся при наведении.**
Причина: нарушен порядок LVHA. Правила `:link`, `:hover` и `:visited` имеют равную специфичность, и последнее по порядку побеждает. `:visited` стоит после `:hover` и задаёт `background: none`, перебивая золотой фон.
```css
nav a:link    { color: white; }
nav a:visited { color: white; }
nav a:hover   { background: #E0A526; }
nav a:active  { background: #B07F14; }
```

**Bug 2. Бейдж прилипает к углу страницы.**
Причина: у `.card` нет `position: relative`. У `position: absolute` блоком отсчёта служит ближайший предок с позиционированием; его нет, поэтому берётся начальный контейнер (окно).
```css
.card  { position: relative; padding: 16px; border-radius: 10px; }
.badge { position: absolute; top: 10px; right: 10px; }
```

**Bug 3. Третья карточка падает вниз на ноутбуке.**
Причина: модель `box-sizing: content-box` по умолчанию. Ширина 33.33% относится только к содержимому, а padding 20px с двух сторон и border 1px с двух сторон прибавляются сверху, поэтому каждая карточка шире трети и три в ряд не помещаются. Исправление: `border-box`, чтобы 33.33% включала отступы и рамку; лучше ещё и сетка.
```css
.card { box-sizing: border-box; width: 33.33%; float: left; padding: 20px; border: 1px solid #ddd; }
/* или современно: */
.cards { display: grid; grid-template-columns: repeat(3, 1fr); gap: 20px; }
```

## 8. Вопросы на защите

1. **Что значит mobile first?** Базовый CSS для телефона без медиа-запросов; на 768px и 1200px через `min-width` только добавляем (2 и 3 колонки).
2. **Почему порядок LVHA именно такой?** У `:link`, `:visited`, `:hover`, `:active` одинаковая специфичность, побеждает последнее правило. `:hover` и `:active` должны идти после `:link` и `:visited`, а `:active` после `:hover`.
3. **Зачем `position: relative` на карточке?** Чтобы `absolute`-бейдж считал `top` и `right` от карточки, а не от страницы.
4. **Что делает `box-sizing: border-box`?** Включает padding и border в `width`, поэтому ширины складываются предсказуемо.
5. **Как считается скидка?** `calculateTotal`: при `people >= 5` скидка равна 10% от суммы, округлённой до центов; итог `subtotal − discount`.
6. **Как форма проверяется без перезагрузки?** Обработчик `submit` вызывает `event.preventDefault()`, затем показывает сообщения через DOM.
7. **Откуда красная звёздочка?** Из CSS: `label.required::after` с `content`. В HTML её нет.
8. **Почему не `!important`?** Он ломает каскад и даёт минус 2 балла. Конфликты решены специфичностью (`.site-header .header-cta`) и порядком правил.
9. **Как работает смена дня и ночи в 3D?** Одна переменная `turn` растёт на 1 при каждой смене темы; по ней считаются положения солнца и луны, цвета неба и огни, поэтому всё согласовано.
10. **Чем Bootstrap отличается от своего CSS?** Он даёт готовые сетку, navbar и карточки: мало своего кода (205 строк против около 700), но есть зависимость и типовой вид.
11. **Что происходит без WebGL или с reduced-motion?** Без WebGL остаётся фото; при `prefers-reduced-motion` анимации выключены, тур открывается сразу.
12. **Зачем `try/catch` у `localStorage`?** В приватном режиме обращение к хранилищу может бросить исключение; сайт должен работать и без него.
